# OPD catalyst expert-router shadow pilot

## Decision boundary

This pilot tests **On-Policy Distillation (OPD)** as an advisory router over
the frozen Standard Transformer, Delta-MHAR, and their ensemble. It does not
replace the numerical models and it does not ask a language model to invent a
catalyst property value.

The implementation is complete, but no OPD scientific effect is claimed until
an independently stronger teacher, programme-held-out prompts, and a new
programme with sealed outcomes pass the frozen gates in
`catalyst_opd_router_design.json`.

```text
target-label-free diagnostics
    -> student causal-LM rollout
    -> teacher logits on the student's visited prefixes
    -> reverse-KL update
    -> strict JSON decision
    -> Standard / MHAR / ensemble
    -> predict / rank / abstain
```

## What is implemented

- exact-schema `RouterState` prompts containing source skill, feature
  availability, uncertainty, expert disagreement, domain distance, and
  composition support;
- rejection of all extra fields, including target outcomes, oracle expert
  identity, and target performance;
- student on-policy sampling followed by full-vocabulary reverse KL against a
  white-box teacher;
- optional teacher-top-k local-support KL for bounded-memory diagnostics;
- exact tokenizer-fingerprint matching between teacher and student;
- strict JSON decisions with fail-closed `abstain` on prose, malformed JSON,
  unknown fields, invalid enums, or invalid confidence;
- optional LoRA student updates;
- atomic reports containing design, prompt, model, tokenizer, training, and
  pre/post-evaluation records;
- a network-off default (`local_files_only=True`).

The implementation follows the defining OPD distinction: the teacher scores
prefixes generated by the current student rather than fixed teacher traces.
The default objective is token-level reverse KL from the student distribution
to the teacher distribution.

## Files

| File | Role |
|---|---|
| `catalyst_opd_router_design.json` | Frozen authority, leakage, evaluation, and promotion contract |
| `catalyst_attention/opd_router.py` | Prompt schema, decision decoder, OPD loss, training loop, and expert-output adapter |
| `run_opd_router_pilot.py` | Local Hugging Face teacher/student execution and audit report |
| `catalyst_opd_router_smoke_prompts.jsonl` | Synthetic algorithm-smoke prompts; never scientific evidence |
| `tests/test_opd_router.py` | Contract, leakage, tokenizer, KL, rollout, and training tests |

## Install and test

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r analysis/catalyst_attention/requirements-opd.txt

PYTHONPATH=analysis python -m unittest tests.test_opd_router -v
```

The tests use a tiny in-memory causal LM. They verify that the generated
tokens come from the student, the teacher supplies logits on those exact
prefixes, gradients reach only the student, and target changes cannot affect a
router prompt.

## Offline-by-default real-model run

After models have been downloaded or copied into local paths:

```bash
PYTHONPATH=analysis python analysis/run_opd_router_pilot.py \
  --student-model /local/path/to/student \
  --teacher-model /local/path/to/teacher \
  --prompts /local/path/to/target_free_prompts.jsonl \
  --steps 100 \
  --lora-rank 8
```

For a low-cost **algorithm smoke only**, the same-family Apache-2.0
SmolLM2-135M/360M pair can be downloaded explicitly:

```bash
PYTHONPATH=analysis python analysis/run_opd_router_pilot.py \
  --student-model HuggingFaceTB/SmolLM2-135M-Instruct \
  --teacher-model HuggingFaceTB/SmolLM2-360M-Instruct \
  --prompts analysis/catalyst_opd_router_smoke_prompts.jsonl \
  --steps 3 \
  --max-new-tokens 48 \
  --allow-download \
  --allow-unqualified-teacher
```

The `--allow-unqualified-teacher` flag is intentionally explicit. A raw small
teacher may fail the strict-JSON gate, so that run verifies infrastructure
only. Without the flag, training stops when teacher validity is below 0.95.

## Required scientific run

Before any real comparison:

1. Build row-level prompts from `ExpertRouterOutput` using only predictions,
   predictive uncertainty, source-calibrated OOD distance, feature
   availability, and composition support. The adapter never reads
   `CatalystSample.target`.
2. Keep programme identity, oracle expert, target labels, and post-outcome
   literature out of the prompt.
3. Demonstrate that the teacher beats the deterministic target-free router on
   a held-out programme. Fluency and JSON validity are not teacher advantage.
4. Compare prompt-only, SFT, off-policy distillation, OPD, teacher, and the
   deterministic router under the same split.
5. Evaluate the downstream routed numerical predictions, not just agreement
   with the teacher.
6. Freeze the resulting student once, then test it on a new external programme
   whose outcomes remained sealed.

Until step 6 passes, every report must retain
`scientific_effect_verified=false`.

## First real-model smoke result

The first same-tokenizer white-box run is complete with
SmolLM2-360M-Instruct as teacher and SmolLM2-135M-Instruct plus rank-4 LoRA as
student. The runner used the models' chat template, four synthetic target-free
states, Apple MPS, one on-policy update, and teacher-top-64 reverse KL.

- the OPD step completed with loss `0.831147`, finite gradient norm `1.4524`,
  and token top-1 teacher/student agreement `0.455`;
- the teacher produced syntactically valid JSON on 4/4 prompts but strict
  schema-valid decisions on 0/4;
- every teacher output selected `standard + predict`, including the explicit
  low-skill, high-uncertainty, low-support abstention case;
- every output also used `mhar` and `ensemble` as invalid reason codes;
- the decoder therefore failed all four decisions closed to `abstain`;
- student strict validity remained 0/4 after one step.

The result validates the real Transformers/LoRA/OPD execution path and rejects
this teacher. Loss reduction or token agreement cannot rescue a teacher that
does not possess the routing behaviour. Continued tuning against the four
smoke prompts is stopped. The compact auditable result is
`results/catalyst_opd_router_smoke_summary.json`; the regenerable local model
and raw completions remain under the ignored checkpoint directory.

## Why this is the appropriate OPD target

The current evidence shows complementary experts rather than one universally
better architecture. OPD can plausibly compress a teacher's routing policy,
but it cannot reconstruct missing ligands, synthesis conditions, active-site
descriptors, or experimental protocols. Those state variables must be
extracted and recorded upstream.

## SFT cold-start follow-up

Two independently seeded LoRA SFT attempts made the 360M teacher emit valid
JSON but failed the frozen held-out routing gate (`14.6%` and `15.7%`
expert/action agreement; `90%` required). The gate stopped OPD both times.
See `OPD_SFT_COLD_START_RESULT.md` and
`results/catalyst_opd_sft_cold_start_summary.json` for the audited negative
result.
